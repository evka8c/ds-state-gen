No design (6)
Offline
screen
 Connection drops: runs, autosave and list fetch fail separately with no unified offline banner. Required No design
Misleading
 No navigator.onLine/offline listener in SQLEditor/, SQLEditorLayout/ or state/sql-editor; React Query v5 (package.json ~5.83) pauses mutations while offline by default (no networkMode override in apps/studio/data/query-client.ts), so a Run while offline leaves isPending true and UtilityTabResults.tsx:41-47 shows 'Running...' until reconnect, then fires.
Misleading. The results panel claims the query is running when nothing was sent, and it may execute later on reconnect against the live database; autosave failures only show a small icon. Retrying doesn't clarify what's happening.
Fix: New offline banner + offline-aware Run state

Undetected destructive query
warning dialog
 Heuristic analyzeQueryIssues may miss destructive SQL (e.g. inside DO blocks); ambiguous coverage. No design
Misleading Edge case
 destructiveSqlRegex (apps/studio/components/interfaces/SQLEditor/SQLEditor.constants.ts:40-50) only matches DROP/DELETE/TRUNCATE at the start or right after ';' or inside EXECUTE strings, so 'WITH d AS (DELETE FROM t RETURNING *) SELECT 1' and 'DO $$ BEGIN DELETE FROM t; END $$' pass checkDestructiveQuery (SQLEditor.utils.ts:127) and run without the RunQueryWarningModal.
Misleading. Users learn the warning dialog as a safety net, so its silence reads as 'this is safe'; the statement runs irreversibly on the live database and neither retry nor refresh undoes it.
